# libSceLibreSsl3 technical debt

### Unknown function info

- [libSceLibreSsl3 pending exports](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) - 72 named callable exports, excluding `CRYPTO_memcmp`, `MD5`, `SHA1`, `d2i_ASN1_INTEGER`, `SSL_CTX_set_min_proto_version`, `SSL_CTX_set_max_proto_version` and the nine `*_up_ref` exports, remain unimplemented from the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceLibreSsl3.c), cross-checked against the same module in PS5 firmware 13.60. Their signatures and behaviour are unverified; the declarations use the no-parameter unknown-signature convention and throw through `NotImplemented_nid_no_patch`.

### Functional

- [ASN.1 integer decoding](../../../core/libs/prx/libSceLibreSsl3/src/IntegerDecoder.cpp) throws on rejected encodings/allocation failures instead of matching native NULL/error handling. Redundant-sign/empty-content rejection retains old output that the module frees and clears. The decoder does not populate the legacy queue; remaining LibreSSL3 ERR exports throw. [13.42 native-PC evidence](https://github.com/boykopovar/AnyPS5/pull/10948#issuecomment-6412137728), using a recording allocator, confirms tested replacement/free order, allocation cleanup and negative-length NULL returns. Nonnegative null input faults natively and throws here. Console/application-heap ABI and untested error-precedence/overflow combinations remain unverified. Contracts follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1). Closes when: error/replacement semantics and console/allocator interoperability are verified.
- [CRYPTO_memcmp](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) follows the public [LibreSSL signature and equality contract](https://man.openbsd.org/CRYPTO_memcmp.3), without PS5 verification. The exact nonzero result for unequal buffers is unspecified by that contract. Content-independent execution of its volatile byte reads still depends on the compiler; inspect optimized code when changing toolchains. Closes when: measured on a PS5 and the supported toolchains' generated code is checked.
- [MD5 and SHA1](../../../core/libs/prx/libSceLibreSsl3/src/Digest.cpp) (libSceLibreSsl3) - follow LibreSSL's [md5.c, sha1.c](https://github.com/libressl/openbsd/tree/bc9483725c5815efb64b6d9acc52fc5fba139212/src/lib/libcrypto) and hash through libSceLibreSsl's `MD5_*` and `SHA1_*`. A null digest buffer, which LibreSSL 4.0.0 does not check, throws. Nothing is checked on the console
- [EVP_PKEY_up_ref and EC_KEY_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - console layouts and retain/release interoperability are unverified. The 32-byte EVP and 64-byte EC layouts, with counters at offsets 4 and 48, follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto) `evp/evp_local.h`, `evp/p_lib.c`, `ec/ec_local.h` and `ec/ec_key.c`. Atomic retains replace its internal mutex; future releases must synchronize with the same counters. With no key constructors/destructors in this module, tests use caller-owned objects without validating allocator or destruction compatibility. Null keys and signed-counter overflow, undefined upstream, throw without mutation. Closes when: console layouts and lifetime interoperability are measured.
- [BIO_up_ref, X509_up_ref, X509_STORE_up_ref and RSA_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - console layouts and retain/release interoperability are unverified. The 112-byte BIO, 216-byte X509, 64-byte X509_STORE and 152-byte RSA layouts, with counters at offsets 80, 28, 56 and 104, follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto) `bio/bio_local.h`, `x509/x509_local.h` (RFC 3779 fields present, a 64-byte hash) and `rsa/rsa_local.h`; the result, the new count above one, follows `bio/bio_lib.c`, `x509/x_all.c`, `x509/x509_lu.c` and `rsa/rsa_lib.c`. Atomic retains replace its locks. `BIO_vfree` and every constructor and destructor of these objects still throw, so tests use caller-owned objects. Null objects and signed-counter overflow, undefined upstream, throw without mutation. Closes when: console layouts and lifetime interoperability are measured.
- [SSL_up_ref, SSL_CTX_up_ref and SSL_SESSION_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - retain the counters at offsets 176, 40 and 184 of `SSL`, `SSL_CTX` and `SSL_SESSION`, as [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl) `ssl_lib.c` and `ssl_sess.c` do, over the `ssl_local.h` fields before each counter (the 48-, 32- and 32-byte key and session-id arrays of `ssl.h`); only those prefixes are mirrored, since nothing else in these objects is used yet. The console layouts are unverified; no constructor or destructor exists here, nulls and overflow throw. Closes when: console layouts and lifetime interoperability are measured.
- [SSL_CTX_set_min_proto_version and SSL_CTX_set_max_proto_version](../../../core/libs/prx/libSceLibreSsl3/src/ProtocolVersion.cpp) follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl/ssl_versions.c) `ssl_versions.c`: version 0 selects the method's bound and clears the protocol version, a DTLS method converts DTLS 1.0 and 1.2 to TLS 1.1 and 1.2 and back, the range is clamped to the method's, and a failure returns 0 without changes. They write the `uint16_t` fields at offsets 128-134 of `SSL_CTX` and read `dtls` (offset 0) and the bounds (12, 14) of the `SSL_METHOD` it points to, the `libssl/ssl_local.h` layouts, mirrored only up to those fields; the console layouts are unverified, and no method or context constructor exists here, so tests build both. A null context or method, dereferenced upstream, throws. Closes when: the console layouts are measured.
